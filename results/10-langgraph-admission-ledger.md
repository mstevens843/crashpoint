# 10 - LangGraph admission ledger containment

Working record for 2026-09-06. This experiment follows from
[`langchain-ai/langgraph#8764`](https://github.com/langchain-ai/langgraph/issues/8764) and measures
the admission/visibility boundary separately from the external-effect ordering race in #8039.

## Question

This fixture kills the process as LangGraph enters its first checkpoint write, before that
checkpoint becomes durable. At that point the checkpoint store has no row, the user node has not
run, and fresh-process `invoke(None, config)` raises `EmptyInputError`. Checkpoint absence cannot
distinguish a run that was never admitted from one a caller accepted immediately before the process
died.

Can a caller-owned acceptance record, committed before dispatch and carrying the original input,
make that distinction and authorize explicit recovery?

## Experiment

Both arms use LangGraph 1.2.11, `langgraph-checkpoint-sqlite` 3.1.1,
`durability="sync"`, and the same deterministic SIGKILL immediately before the first
`SqliteSaver.put()`.

| Arm | Durable fact before dispatch | Recovery rule |
|---|---|---|
| `runtime_only` | none outside LangGraph | checkpoint absence is not admission evidence; remain `UNVERIFIED` |
| `external_admission_ledger` | caller commits `thread_id`, original input, and `accepted` event | accepted + zero checkpoints becomes `ADMITTED_BUT_RUNTIME_EVIDENCE_MISSING`; replay stored input and append completion |

The acceptance store is a separate SQLite event ledger. The run identity and original input are
immutable, and recovery appends `recovery_required` and `completed` rather than overwriting the
acceptance fact. The external effect is still counted by crashpoint's out-of-process ledger, not by
LangGraph or the recovery process.

Command:

```bash
uv run --extra langgraph python -m crashpoint.harness.langgraph_admission \
  --k 30 --name langgraph_admission
```

## Result

All 60 crash/recovery trials matched the prewritten arm rules.

| Observation | `runtime_only` | `external_admission_ledger` |
|---|---:|---:|
| trials matching rule | 30/30 | 30/30 |
| subject exit code | -9 | -9 |
| checkpoints before recovery | 0 | 0 |
| effects before recovery | 0 | 0 |
| initial recovery | `EmptyInputError` | `EmptyInputError` |
| decision | `UNVERIFIED` | `ADMITTED_BUT_RUNTIME_EVIDENCE_MISSING` |
| explicit replay | no | yes |
| checkpoints after recovery | 0 | 3 |
| effects after recovery | 0 | 1 |
| final admission status | missing | completed |

The treatment event sequence was `accepted -> recovery_required -> completed` in all 30 trials.

## Claim boundary

This is application-level containment, not a LangGraph source fix. It demonstrates that an
authoritative caller-owned record can preserve admission and the input needed for explicit replay
when LangGraph has no checkpoint.

It does not make arbitrary external effects exactly-once. Before replaying a real payment, email,
trade, or tool call, the application still needs authorization checks, an idempotency key fixed
before nondeterministic work, durable attempt records, and reconciliation with the destination.
The fixture's single effect occurs only after the pre-first-checkpoint crash, so it does not test a
crash after an external effect has crossed.
