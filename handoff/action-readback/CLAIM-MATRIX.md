# Claim matrix

Every claim this experiment supports, its supporting artifact/test, and its explicit boundary.
Nothing below is claimed without an entry here. The "offline verifier independently re-derives
every decisive fact" row below reflects the POST-Round-6 verifier (see `SELF-REVIEW.md`): an
independent review found 12 real gaps in that claim as it stood after Round 1 alone, and four
further self-audits performed the same way afterward found 20 more (11 at the per-trial level, 2
at the manifest level, 5 at the schema-internal-consistency/evidence-completeness level, 2 at the
derive-function-recomputation/duplicated-field level) - 32 total, all now fixed and each with its
own permanent test.

| Claim | Supporting artifact/test | Boundary |
|---|---|---|
| A fresh, opaque action ID is minted before dispatch and never derived from mutable args/external event/tx hash | `action_readback.run_trial` mints via `uuid.uuid4()` before any admission write; `test_action_readback_receipt.py`'s fixtures never construct an action_id from payload content | Boundary of this local fixture's own admission table, not a claim about any other system's ID scheme |
| The admission commit is independently confirmed durable before Worker A is spawned | `admission_commit_confirmed` field + the dispatch-gate control flow in `run_trial`; `test_injected_admission_readback_confirmation_failure_is_a_clean_gate_rejection` proves Worker A is never spawned when this fails | Confirms durability against a KILLED WORKER process on this host, WAL+`synchronous=FULL` recorded per trial - not a host power-loss or fsync-hardware test |
| Worker A reads its own committed action record independently, not from argv | `action_readback_runtime.dispatch_role` calls `read_admission` via a fresh connection; `admission_read` event retained in `worker_a.stdout` and cross-checked by the offline verifier | Same-process-tree trust: the worker process itself is not adversarial in this fixture |
| Action ID, attempt ID, and receiver event identity are three distinct fields, never conflated | Schema (`action_readback_receipt.py`): `action_id`, `worker_a_attempt_id`/`worker_b_attempt_id`, raw ledger `attempt_id` per record; `derive_external_outcome` never substitutes one for another | N/A - structural, always holds by construction; verified, not assumed, via `test_mutation_reversed_raw_attempt_order` and `test_mutation_effect_identity_substituted...` in the verify suite |
| Two intended actions with identical payloads get distinct action IDs, never merged | `test_checked_in_evidence_two_admitted_clean_trials_are_distinct_actions_same_payload` (real batch) and `test_mutation_two_distinct_admitted_actions_with_identical_payload_are_not_merged` (verifier, disabled-check proof in SELF-REVIEW.md) | Checked for this fixture's own 18-trial batch; not a claim about arbitrary-scale collision resistance |
| An effect recorded under the right action ID but a different payload is exposed as a mismatch, never folded into intended-action success | `payload_mismatch` case, 3/3 trials `external_outcome=ONE_EFFECT_MISMATCHED`; `digests_match_admission` recomputed independently offline; disabled-check proof in SELF-REVIEW.md | The mismatch is detected via payload digest comparison against the receiver's retained record; it does not detect a mismatch the receiver itself never digested |
| The receiver ledger records every distinct external effect, never silently deduplicating under this experiment's unkeyed calls | `crashpoint.ledger.core.LedgerState._crossed` (shared, proven infra, unmodified); `naive_retry` measured 2 effects, not 1, in 3/3 trials | Authoritative only for this local harmless fixture; not a payment provider, not a claim about any other system's dedup behavior |
| A real, on-disk, zero-byte baseline is established and independently verified before every trial | `_reset_and_establish_baseline`; disabled-check proof (Part C) shows a stale-file fault IS detected by the real code and is NOT detected once the check is removed | Verified for THIS fixture's own reset path; not a general filesystem-durability claim |
| Fresh observation is by a separate process with its own file handle, never a worker's claim or a live daemon dump | `action_readback_runtime.observe_role`, spawned as `python -m ... observe` per trial; required-worker-event and observer-exit-status checks in the offline verifier | The observer trusts the OS filesystem read it performs; it does not defend against a hostile OS or a compromised interpreter |
| A deliberately denied readback is reported as unverified/indeterminate, never as zero effects, missing externally, confirmed, or safely replayable | `unavailable_readback`, 3/3 trials: `effect_count=null`, `external_outcome=INDETERMINATE`, `observation_availability=UNAVAILABLE`, `externally_verified=False`, `injected_fault='observer_evidence_denied'` (structurally required by `validate_receipt` for exactly this case) | Distinguishes THIS fixture's intentional negative control from an accidental infrastructure failure via the labeled field; does not generalize to every possible evidence-loss mode in every system |
| A deliberately incomplete-observation control can match its own prediction (`passed=True`) while never being externally verified | `unavailable_readback`'s `passed=True` alongside `externally_verified=False` in all 3 trials; `derive_externally_verified` kept structurally distinct from `passed` in `validate_receipt` | These are deliberately two different booleans on purpose; a reader who conflates them is misreading the schema, not the schema itself conflating them |
| The offline verifier independently re-derives every decisive fact from retained raw bytes, never trusting the producer's summary | `action_readback_verify.py`'s own, separately-written ledger JSONL parser (not imported from `action_readback_runtime.py`); admission SQLite re-read via raw `sqlite3`; recomputed `cells_summary`/`all_agree`/`trial_count`; `validate_receipt` now also recomputes `external_outcome`/`observation_availability`/`client_claim` via the schema's own `derive_*` functions from the raw fields, closing the one case (`unavailable_readback`) where the file-based ledger cross-check cannot run at all; 27+ one-mutation tests each asserting a specific rejection reason | Verified against THIS bundle's schema version; does not claim to detect a coordinated rewrite of every retained file with no external trust anchor (see FIELD-MAPPING.md's note on this) |
| Required source/lock/prediction provenance is bound and independently checked | `REQUIRED_EMBEDDED_SOURCE_FILES`/`REQUIRED_EMBEDDED_LOCK_FILES` imported directly from the schema module by the verifier (not read from the manifest's own possibly-tampered list); `test_mutation_omit_verifier_source_from_embedded_inventory`, `test_mutation_altered_prediction_sha256`, `test_mutation_altered_retained_prediction_content` | A matching self-contained hash proves consistency with retained bytes, not independent external authorship |
| No unbounded wait anywhere in the harness; every subprocess is reaped | `_BARRIER_TIMEOUT`/`_EXIT_TIMEOUT`/`_ROLE_TIMEOUT`/`_LEDGER_STARTUP_TIMEOUT`, all `selectors`-bounded; `_reap_owned` called from both the exception path and `finally`; `test_wait_for_barrier_bounded_timeout_on_a_process_that_never_emits_it`, `ps aux` check after the full suite shows no owned processes remaining | Bounded on THIS host under THIS test's timeouts; not a claim about behavior under extreme system load |
| A batch-level trial failure does not crash the whole run, and is never silently dropped or duplicated | `test_run_level_aggregates_a_trial_failure_without_crashing_the_batch` (real `run()`, not `run_trial()` alone); `test_injected_journal_append_failure_records_execution_failure_not_a_crash` | Distinguishes ordinary observation/execution failure from a treated-as-fatal primary-storage failure (manifest write) - see SELF-REVIEW.md's rationale |

## Explicitly NOT claimed

- No claim about SafeAgent, CrewAI, LangGraph, or any specific commercial pilot; no code in those
  projects was touched.
- No claim that a "SafeAgent Control" comparison was executed - `FIELD-MAPPING.md`'s adapter
  status is explicitly NOT RUN, and no SafeAgent Control command or SABLE schema field is invented
  anywhere in this handoff.
- No distributed-fencing, stale-owner-overlap, or multi-host claim.
- No statistical reliability-rate claim from 18 predeclared trials.
- No claim that complete, coordinated rewriting of every retained file in a bundle (raw ledger,
  admission SQLite, receipts, journal, and the manifest's own receipt hash, all consistently) is
  detectable without an external trust anchor - the verifier detects internal inconsistency, not
  a hypothetical adversary with write access to the entire bundle who also recomputes every hash
  correctly.
