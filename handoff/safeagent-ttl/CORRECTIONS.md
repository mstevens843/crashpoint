# Corrections applied 2026-09-19 (same-day review)

An independent review supplied a reproduction script
(`/private/tmp/safeagent-ttl-review-2026-09-19/check_review.py`, referenced here for provenance,
not committed - it is a review artifact, not part of this experiment) that ran the actual
production code (`crashpoint.harness.safeagent_ttl.run_trial`,
`crashpoint.harness.safeagent_ttl_verify.verify_bundle`) against the original evidence bundle and
against targeted fault injections. Every finding below was independently re-reproduced in this
session, against this code, before any fix was written - not accepted on the reviewer's word.

**Not in dispute:** the central empirical result. `verify_bundle` against the original,
untouched bundle returned zero problems, and an independent re-parse of all 30 trials' raw ledgers
and final SQLite snapshots agreed with the reported matrix. What follows are the harness's and
verifier's own bugs, not disputes of what was measured.

## Structural fixes not tied to one specific injected mutation

| Area | Fix | Test/evidence |
|---|---|---|
| `_wait_past_ttl`'s bounded-wait deadline was provably unreachable (`deadline = cutoff + margin`, so `now >= cutoff` always fires first) | the monotonic deadline is now computed independently, from `time.monotonic()`, not derived from the wall-clock `cutoff` | `tests/test_safeagent_ttl.py::test_wait_past_ttl_actually_waits_and_confirms_crossing` (existing; the fix does not change this test's behavior, since it exercises the now-genuinely-reachable normal path) |
| The shared `LedgerDaemon.__enter__` (`ledger_process.py`) waits for readiness with a blocking `readline()` inside a nominal timeout loop - a real unbounded-wait risk, left unfixed there deliberately (see below) | a local `_BoundedLedgerDaemon` in `safeagent_ttl.py`, using the same `selectors`-bounded pattern as `wait_for_barrier`, used everywhere this experiment starts a ledger daemon | exercised by every live test and by the confirmatory batch itself; `ledger_process.py` was not modified, so every other experiment's behavior is unchanged |
| Release-version enforcement: nothing confirmed the installed version actually matched the release under test | `_release_info` now raises if `importlib.metadata.version()` disagrees with the intended release, aborting the run rather than silently measuring the wrong package | exercised implicitly on every run (both releases matched in the recorded batch), **and directly** by `tests/test_safeagent_ttl.py::test_release_info_aborts_on_a_genuine_venv_version_mismatch` (added in the second review pass): this calls the real 0.1.24 venv but asks `_release_info` to confirm 0.1.23, a genuine mismatch produced without any third distribution or mock - the original claim that no such test was possible was itself wrong |
| Provenance binding: the bundle recorded a hardcoded wheel hash and a freshly-computed module hash, but never embedded the actual source bytes those hashes describe, and never embedded the prediction bytes `prediction_sha256` claims to hash | `run()` now embeds, per run: this experiment's own harness/runtime/receipt/verifier source, the ledger core/daemon source, `canonical.py`, each release's actual `sqlite_store.py`, and a byte-identical copy of the frozen prediction, all under the bundle's own `sources/`/`prediction.json`, with hashes recorded in the manifest and checked by the offline verifier | `tests/test_safeagent_ttl_verify.py::test_mutation_provenance_fabricated_end_to_end` covers the check path; the embedded files themselves are present in `evidence/safeagent_ttl/safeagent_ttl_corrected/sources/` |
| A trial-execution exception could crash the whole 30-trial batch with no account of which trials completed | `run()` now catches a `run_trial` exception per trial, records it in a separate `execution_failures` list (never silently dropped), continues the batch, and marks the manifest `status` `INCOMPLETE` (with `all_agree` forced `False`) rather than a success-shaped partial result; the manifest is rewritten incrementally after every trial, not only at the end | the confirmatory batch itself completed with zero execution failures and `status: COMPLETE`. That gap is closed by `tests/test_safeagent_ttl.py::test_run_level_aggregates_a_trial_failure_without_crashing_the_batch` (added in the second review pass), which patches `run_trial` to fail on one of two trials and calls the real `run()`, asserting `status=="INCOMPLETE"`, `all_agree is False`, `trial_count==1`, `expected_trial_count==2`, and exactly one recorded `execution_failures` entry |

## Interpretation and wording corrections (report)

`results/12-safeagent-ttl.md` previously said the `0.1.24` pre-effect claim "stays PENDING
forever" and called it "the more consequential row," and implied `settle()` would have to be
called with a fabricated result to resolve it. All three are corrected: the report now states only
what was measured (zero effects, denied retry, `PENDING`, and no automatic release through the
tested API surface), removes the unsupported ranking, and clarifies that `settle()` can be called
with a truthful reconciliation result (a caller-confirmed failure or cancellation) without ever
having to assert the external effect occurred. The report also now precisely separates
`sweep_stale_pending()` (returns 0, does nothing) from `count_stale_pending()` (reports the count,
mutates nothing) rather than letting the upstream commit message's own looser framing stand
unexamined.
